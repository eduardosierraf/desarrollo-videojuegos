Fundamentos

¿Qué es el game design?

  1. 01¿Qué hace el jugador?La acción principal dentro del juego
  2. 02¿Por qué lo hace?El objetivo o la motivación detrás de esa acción
  3. 03¿Cómo se siente al hacerlo?La emoción que deja esa experiencia

No es el arte, ni el código, ni la historia — es decidir la experiencia detrás de todo eso.

Panorama

Géneros de videojuegos

Plataformas

Saltos, precisión de movimiento, niveles con obstáculos

Shooter

Puntería, reflejos, gestión de munición y vida

Puzzle

Lógica, patrones, resolución de problemas paso a paso

RPG

Progresión de personaje, narrativa, decisiones a largo plazo

Estrategia

Planificación, gestión de recursos, visión de conjunto

Terror / Survival

Tensión, escasez de recursos, control del ritmo y el miedo

Cada género trae mecánicas y expectativas propias del jugador.

Decisión del semestre

Elige tu ruta: 2D o 3D

Ruta A · 2D

Movimiento lateral, plataformas, colisiones simples. Curva de aprendizaje más suave, física y cámara predecibles. Ideal para plataformas, puzzle o arcade.

Ruta B · 3D

Espacio, cámara y colisiones con mayor complejidad. Más variables — profundidad, cámara, iluminación. Ideal para exploración, shooter o survival.

La ruta elegida se mantiene fija durante todo el semestre.

Documentación

¿Qué es un GDD?

El Game Design Document es el mapa de tu juego antes de programarlo.

  1. 01Comunica la visiónTodo el equipo entiende el mismo juego
  2. 02Alinea decisionesEvita que cada quien programe una idea distinta
  3. 03Mide el alcanceDefine qué entra y qué queda fuera del semestre
Estructura

Secciones de un GDD

  1. 01Concepto e historiaPremisa en una frase, contexto narrativo si aplica
  2. 02Mecánicas y controlesAcciones del jugador, teclas o botones, reglas
  3. 03Niveles y progresiónDificultad creciente, objetivos por nivel
  4. 04Arte y sonidoEstilo visual, referencias, efectos y música
Diseño

El core loop

El ciclo de acciones que el jugador repite una y otra vez — sostiene el juego minuto a minuto.

  • Explorar

Sin un core loop claro, el jugador termina una acción y no sabe qué sigue.

Antes de programar

Prototipado rápido en papel

  1. 01Boceta las pantallas principales
  2. 02Explica el juego a un compañero sin mostrarle nada
  3. 03Juega la mecánica core con fichas, cartas o dados
  4. 04Anota qué reglas confundieron a quien probó
  5. 05Ajusta el GDD antes de escribir una sola línea de código
